    2.3.3 联网搜索子agent编写
       步骤1: 定义工具
            from langchain_core.tools import tool
            from tavily import TavilyClient
            import os
            from dotenv import load_dotenv
            from api.monitor import monitor

            load_dotenv(override=True)

            tavily = TavilyClient(api_key=os.getenv("TAVILY_API_KEY"))

            @tool
            def internet_search(query:str,max_results:int=10):
                """
                  进行联网搜索信息的工具! 专门用于查询数据库和rag知识库之外的数据!
                :param query: 查询的问题
                :param max_results: 返回的结果的数量,默认是10条
                :return: 查询的结果
                """
                print(f"[联网搜索智能体]internet_search工具开始被调用,参数为:{query},{max_results}")
                # 向前端发送消息!
                monitor.report_tool(tool_name="internet_search",args={"query":query,"max_results":max_results})
                result = tavily.search(
                    query=query,
                    max_results=max_results,
                    include_answer=True  # 总结
                )
                print(f"[联网搜索智能体]internet_search工具调用结束,查询结果为:{result}")
                return result

       步骤2: 定义子智能体

      步骤3: 主智能体执行代码(粘贴)
         1. 前置准备函数 _prepare_session_environment(thread_id)
             返回1: output文件的完整地址(给前端/用于前端展示上传和生成的文件信息)
             返回2: output下的相对地址(给模型,添加到提示词,用于控制模型生成文件的位置 例如: 生成药品.pdf /output/session_123/药品信息.pdf)
             返回3: upload_info:str 这是一段提示词,如果有上传的文件, 将上传文件地址拼接到提示词,让agent进行读取
             注意: 为啥存在output和updated两个文件夹!
                 output用于读取生成和上传文件(所以,上传文件需要从updated复制到output一份)
                 updated专门用于存储上传文件,要告诉模型,然后模型用内置工具进行读取
                 不能使用一个文件的原因就是因为,模型可能会把生成和上传都混为一谈,都读取到了提示词中
         2. _process_stream_chunk(chunk)
            流式结果的处理!
              1. 调用子智能体
              2. 最终返回结果
              舍弃
              1. 调用工具  -> 工具里面使用 monitor.report_tool...
              2. 调用工具的结构
         3. async def run_deep_agent(task_query: str, thread_id: str = None)
            前端 -> 提问 -> http -> fastapi接口 -> 调用我们异步函数 -> main_agent
            参数1: task_query 问题  main_agent messages : HumanMessage(content = "提示词")
            参数2: thread_id 会话id 区分存储位置 / 推送信息 / 区分聊天记录...

            本质就是异步执行 astream  -> chunk -> 推送数据 1. 调用工具 2. 调用子智能体 3.最终结果

3. 深度搜索项目运行
   3.1 接口分析
       /api/task -> 触发任务启动 -> 调用主智能体
       /ws/{thread_id} -> 创建websocket对象 -> 并且使用thread_id key -> {thread_id:websocket}
   3.2 运行结果反馈(推送数据到前端)
       方案1: 轮询 前端固定的周期访问 [缺点: 性能差,空循环,不及时循环]
       方案2: 后端推送 sse / websocket
   3.3 协程(task)本地变量
       ContextVar: 为单一协程存储数据
       作用: 在连续的调用过程不用传递参数,利用存和取的思路实现间接的传递! (外卖小哥-> 货架 -> 我们)
       本次我们用它共享thread_id

4. 前后端交互流程说明 [图解]

    流程1: 存储websocket -> dict
    流程2: 执行 -> 存储协程本地变量 -> 调用过程推送数据 (tool /subagent /最终结果)

    asyncio.run_coroutine_threadsafe(
                                self.websocket_manager.send_to_thread(payload, thread_id),
                                manager_loop  # uvicorn的循环事件中
                            )

    原则: 在哪个循环事件创建的对象,必须在哪个循环事件中执行!!
    websocket -> 接口 -> uvicorn -> 循环事件 -> uvicorn

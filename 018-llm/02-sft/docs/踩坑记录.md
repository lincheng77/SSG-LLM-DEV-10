# 踩坑记录：微调后评测准确率为 0

## 现象

SFT 微调（full / LoRA）训练正常，但评测准确率始终为 0（基线 28%）。

## 原因（两个 bug 叠加）

1. **训练目标写错**（`message.py`）
   `json.dumps(exapmle.pop('text'))` 把用户输入文本当成了期望输出，模型被训练成"复述用户文本"。
   修复：改为 `json.dumps({'intent': ..., 'slots': ...})`。

2. **datasets 缓存命中旧数据**（关键陷阱）
   改完代码重新训练，模型仍然学复述。原因是 `dataset.map()` 的缓存指纹只记函数名
   （`message.to_message`），不含代码内容，改代码后指纹不变；
   SFTTrainer 内部 tokenize 的缓存命中了修改前的旧数据。
   修复：训练脚本开头加：

   ```python
   from datasets import load_dataset, disable_caching
   disable_caching()
   ```

## 排查技巧

对比两次训练 checkpoint 里 `trainer_state.json` 的 `num_tokens`：
数据变了它必须变。前后完全一致（102784）= 用了同一份缓存。

## 最终结果（test 集，严格匹配 intent + slots）

| 模型 | 准确率 |
|---|---|
| 基线 Qwen3-0.6B | 0.28 |
| 全参微调 | 0.61 |
| LoRA 微调 | 0.48 |
